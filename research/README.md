# Research track

This directory defines a reproducible research track for evaluating reliability patterns in cloud-native data pipelines.

## Research question

How do explicit reliability controls—idempotency, bounded backfills, data-quality assertions, structured failure metadata, and audit logging—affect correctness, recoverability, and operational cost in repeatable pipeline-failure scenarios?

## Scope

The evaluation uses only synthetic or public data and independent reference implementations. It must not contain employer/client code, schemas, data, screenshots, tickets, architecture, internal metrics, or confidential implementation details.

## Planned experiments

1. Duplicate-event replay and idempotency.
2. Late-arriving data and bounded backfill.
3. Null/duplicate business-key detection.
4. Stale-data/freshness detection.
5. Task failure with structured operational metadata.
6. Recovery after partial processing.

## Measurements

- correctness: duplicate/missing output rows
- detection rate: injected faults detected
- recovery: successful deterministic rerun
- runtime: wall-clock duration under controlled conditions
- processing overhead: reliability checks versus baseline
- audit completeness: required metadata fields present

## Reproducibility rule

Results are generated by executable experiments. Numbers must never be hand-entered as research findings. Raw outputs should be retained under `research/results/raw/` and summarized by scripts.

## Publication status

No manuscript or repository material should be described as peer reviewed or published research until that status is actually obtained.
