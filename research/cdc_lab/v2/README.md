## Preservation and audit

All 85 pre-existing tracked files are SHA-256 protected in `BASELINE_INTEGRITY.json`.
The original Paper 2 protocol, runner, tests, manuscript source/PDF and run-1 CSV/JSON
are untouched. Frozen V4/V5 and all historical research files are unchanged. The
submitted ACMSE Paper 1 manuscript is absent from this checkout, so its textual/claim
overlap cannot be assessed here; no Paper 1 content is edited or imported. The owner
must review that source and concurrent-submission policy before submission.

Confirmed original behavior: unbounded remembered IDs, retained tombstones,
whole-stream conflict validation, maximum-version batch oracle, serialized logical
checkpoint and replay, three policies, final-state and redelivery invariants.
No durable storage, source/sink transaction or real CDC connection is implemented.
Original duplicate and delete/reinsert conditions also shuffle records. The original
monotonicity result combines attempted and recovered transitions; it is not solely a
committed-state violation measure. V2 separates attempted, retained-prefix and
recovered-write violations; rollback is represented as a restore, not a stale write.

Output/report paths must not exist. Artifact verification checks all SHA-256 entries
and CSV/JSON field parity, not merely counts. No historical output is regenerated.
Timing/environment/source metadata will differ on rerun. The comparison deliberately
excludes timing and checks every other row field and original configuration/hash.
It is independent execution of the same implementation, not independent implementation
replication. Verify historical integrity with `verify.preserve(Path('.'))` or tests.

## Live interface and verification

See `WALKTHROUGH.md` for the tested five-minute script. The UI selects nine scenarios,
three policies, ordering, seed/key count, checkpoint/interruption, capacity and
whole-input/online validation. It displays trace states and decision reasons, actual
versus canonical state, incorrect keys, counters and scope limitations. All state is
request-local. HTML/JS is embedded in the Python module and has no CDN dependency.

Browser test dependency (UI itself has no dependencies): Playwright 1.62.1 with
Chromium. `node tests/cdc_browser_smoke.cjs` executes real controls. Optional variables:
`CDC_DEMO_PYTHON` (installed-wheel Python), `CDC_DEMO_CWD` (`/tmp` for isolated
installation), `CDC_BROWSER_EXECUTABLE` (system Chromium), `CDC_SCREENSHOT` (new path).
The automated baseline failure renders within 60 seconds; the recorded local check
reproduced it in 2.165 seconds. This is not a user-study or production measurement.

The first local isolated build attempt failed because PyPI was blocked; the stale
wheel consequently lacked the UI. That failure was diagnosed, not counted as a pass.
A new wheel/source distribution was built using the already installed setuptools
84.0.0 and wheel with the build frontend's `--no-isolation` option, then installed
with `--no-deps`. The real-browser test passed from that installed wheel in `/tmp`.
GitHub CI uses the normal isolated build path and a dedicated live-browser workflow.
