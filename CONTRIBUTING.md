# Contributing

Thanks for your interest in contributing to the GCP Data Pipeline Reliability Kit.

## What contributions are useful?

We welcome:

- bug fixes
- additional tests
- clearer documentation
- reusable reliability patterns
- production lessons that can be expressed generically
- examples using fictional or synthetic data
- improvements to safety and observability

## Contribution rules

1. Do not submit proprietary employer or client code.
2. Do not submit confidential schemas, identifiers, screenshots, or production data.
3. Prefer small, reviewable pull requests.
4. Include tests for behavioral changes where practical.
5. Explain the reliability problem being solved, not just the code change.
6. Keep examples cloud- and project-safe unless a Google Cloud-specific implementation is intentional.

## Development approach

Before implementing a larger feature, open an issue describing:

- the problem
- expected behavior
- failure modes
- proposed interface
- test approach

## Pull requests

A good pull request should include:

- a clear title
- concise problem statement
- implementation summary
- tests or validation notes
- documentation updates when behavior changes
